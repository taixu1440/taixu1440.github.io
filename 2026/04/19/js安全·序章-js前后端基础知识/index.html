js安全·序章--js前后端基础知识

发表于2026-04-19|更新于2026-07-16|-training
|浏览量:

从本章开始，我们就要接触js，即JavaScript安全，这也要求更严苛的逻辑链构造和代码审计能力。

在序章中我们将介绍一些之前为了赶路并没有弄清楚的web基础知识，以支撑后续对js代码的审计及其安全的理解。

前端和后端

下面我们将用在web方向已经学过的编程语言解释一下网页前端和后端的概念

前端技术 (Frontend)

浏览器的”母语”（能直接执行的语言）只有三种，能反映为网页的输出，查看网页源代码一般看得见：

  • HTML（结构）

  • CSS（样式）

  • JavaScript（逻辑）

浏览器内置的JavaScript引擎（如Chrome的V8）只能理解JavaScript代码，不能直接执行Python等属于后端

的语言。

后端技术 (Backend)

这些语言和框架运行在服务器上，用户看不见：

  • Python：一门后端编程语言（就像后厨的厨师长，负责指挥和做菜）

  • Flask：一个用Python写的后端框架（就像后厨的一套标准化厨具和流程，让厨师长更高效地工作）

  • PHP：一门专门为Web后端设计的编程语言（老牌厨师，专门做网站后台）

  • Jinja2：一个模板引擎（它有点特殊，需要单独解释）

边界技术：Jinja2 (模板引擎)

Jinja2 是一个很好的例子，它能帮你理解前后端如何“交汇”。

  • 它运行在后端（Python/Flask里）：后端用Python查出数据（比如用户名“张三”），然后交给Jinja2。

  • 它生成前端内容（HTML）：Jinja2把“张三”填进一个HTML模板里，生成一个完整的HTML页面，再发送给浏览器。

  • 最终呈现在前端：浏览器显示“欢迎你，张三”。

流程：
后端(Python) -> 数据(张三) -> Jinja2模板引擎 -> 完整的HTML页面 -> 发送到浏览器(前端)

网页源码的可见情况

查看网页源代码，你一般能看见 HTML 和 CSS，也能看见 JavaScript 的代码或引用链接。

这是一个很实际的问题。基于我们刚讨论的“浏览器母语”理论，答案非常直接：

你“看得见”什么？（网页源代码中）

当你右键点击网页，选择“查看网页源代码”时，你看到的是浏览器收到的、最原始的 HTML 文件内容。

  1. HTML (100% 可见)

    • 所有的标签 <div>、<p>、<a>、<h1> 等。

    • 网页的文字内容（虽然可能混在标签里）。

    • 这是源代码的主体。

  2. CSS (两种情况)

    • 写在HTML内部：<style> 标签里的 CSS 代码，完全可见。

    • 外部文件：<link rel="stylesheet" href="style.css"> 这样的链接，你看不见 style.css 文件里的具体内容，只能看见这个引用。

  3. JavaScript (两种情况)

    • 写在HTML内部：<script> 标签里的 JS 代码，完全可见。

    • 外部文件：<script src="app.js"></script> 这样的链接，你看不见 app.js 文件里的具体代码，只能看见这个引用。

你“看不见”什么？（网页源代码中）

  1. 任何后端语言代码 (PHP, Python, Java, Node.js 等)

    • 原因：这是我们刚刚讲的核心法则，后端代码在服务器上就已经执行完了，永远不会发送到浏览器。

    • 你看到的是结果：比如，后端 PHP 代码 <?php echo "Hello"; ?> 执行后，你看到的源代码里只有 Hello。你永远看不到 PHP 代码本身。

  2. 通过 JavaScript 动态添加到页面的内容

    • 这是另一个常见误区。“查看网页源代码”看到的是服务器最初返回的那个 HTML 文件。

    • 如果页面加载后，JS 代码执行了 document.body.appendChild(...) 添加了新内容，这些新内容不会出现在“查看网页源代码”里。

    • 想看这个：你需要用浏览器的“开发者工具”(F12) -> Elements/元素 标签页，那里看的是实时、动态的 DOM 树。

JavaScript(js)、Nodejs和java

结合新学的前后端知识，我们再来分析这三个术语的区别

JavaScript

JavaScript 是一门主要运行在浏览器中的编程语言，它是浏览器能直接理解的三种”母语”之一（另外两个是 HTML 和 CSS），因此最初专门为前端开发设计，负责实现网页的交互逻辑（如按钮点击、动画效果、发送网络请求）。但后来，JavaScript 借助 Node.js 这个运行环境，也能跑到服务器上做后端开发。它的语法灵活、动态类型，是当今 Web 开发中唯一能横跨前后端的语言。简称 JS。

Node.js

Node.js 不是一门新语言，而是一个让 JavaScript 能够在服务器端运行的后端环境。 你可以把它理解为 JavaScript 的”后厨灶台”——没有它，JS 只能困在浏览器里做前端交互；有了它，JS 就能像 Python 或 Java 一样操作文件、连接数据库、创建 API 服务器。Node.js 基于 Chrome V8 引擎，采用事件驱动和非阻塞 I/O 模型，特别适合高并发的实时应用。它让前端开发者可以用同一门语言 JS 写后端，因此成为全栈开发的利器。

Java

Java 是一门前端完全看不见、专门跑在后端的独立编程语言，和 JavaScript 除了名字相似，没有任何血缘关系。 Java 作为一门后端语言，其需要编译成字节码，再在 JVM（Java 虚拟机）上运行，以”一次编写，到处运行”的跨平台能力著称。它语法严谨、静态类型，适合构建大型企业级系统（如银行、电商、大数据平台）。虽然 Java 也能通过 JSP、Thymeleaf 等技术生成 HTML 发给浏览器，但浏览器收到的永远是纯 HTML/CSS/JS，永远看不见 Java 代码本身。

Try语句

try 是 JavaScript（以及很多其他编程语言）中用于处理错误的关键字。

它的核心思想是：“尝试”执行一段代码，如果出错了，不要崩溃，而是“捕获”这个错误，进行妥善处理。

有 try 的时候，程序就有机会“自救”。

异步操作函数await与async

async 用来标记一个函数是”异步函数”，await 用来等待一个异步操作的结果。

即async 给函数发了个”异步许可证”，await 是函数内部的”暂停键”。

JavaScript 是异步的，JavaScript 执行代码时，遇到耗时操作（比如网络请求、读文件）不会等着，而是先跳过，继续往下执行。

这就导致一个问题：如果你需要等结果回来再继续，直接写不行。.

因此我们可以使用 async/await 函数来解决这个问题

Express中间件

Express 是一个基于 Node.js 的 Web 应用框架，用来快速搭建后端服务器和 API 接口。

Node.js 本身虽然能创建服务器，但非常原始。用原生 Node.js 写一个简单的路由：

Express 帮你自动处理了：

  • 路由匹配（不用手动 if-else 判断 URL）

  • Body 解析（不用手动拼接数据）

  • 响应格式化（不用手动设置头、JSON 序列化）

中间件机制

Express 的精髓在于中间件

  • 每个中间件都能访问 req、res、next

  • 可以修改请求/响应（比如给 req 添加属性）

  • 可以提前结束请求（比如验证失败直接返回 401）

  • 调用 next() 才会进入下一个中间件，否则流程卡住

req, res, next

req, res, next是 Express 框架的核心三要素

中间件的写法中，req，res，next是它的三个固定参数。

next()表示往程序下方继续访问中间件，如果有适配于该路径的中间件，例如全局中间件，母路径中间件，就会直接运行它

需要注意的是，每个中间件都相当于一个函数，如果用了return提前结束这个函数，那就不会再运行next()
