[问题3/文件包含/源码审计]PHP File Contains

这题当时分值高，看都没看就放弃了，实际上也就是个简单的源码审计

第一行是个类似三目运算符的东西

大概是从 URL 参数 blob 中获取值，如果不存在，则使用 $defaultEnvelope 转换后的 base64 编码作为默认值。

然后第三行，是先把payload给base64解码，再json解码，也就是我们要传入一个json形式的base64编码

567行就是对target这个键又进行了删除前后空格和base64解码的处理，随后9行是对黑名单的效验

但看到17行这个url解码，问题就出来了，为什么是先校验，再解码呢?这里就引发漏洞了

我们完全可以让键target的结果进行base64解码后为一串危险的url编码，这当然可以绕过字符串的效验

但21行后，还要求带read=convert.base64-encode（这不是禁了，这是false报error，要的是true），随后进行php协议的拼接

也就是说我们只要给blob传入以下json的base64编码，注意target的值还要先进行url编码，再进行base64编码，也就是它到最后是三层编码
