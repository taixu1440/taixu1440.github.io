漏洞利用

沙盒是一个限制代码执行环境的机制，比如：

  • 禁止导入某些危险模块（os, subprocess）

  • 删除危险内置函数（import, open）

  • 限制全局/局部变量访问

逃逸 = 突破这些限制，执行系统命令或读取任意文件

python沙盒逃逸=命令执行+代码操作

我们必须利用 Python 的动态特性，通过各种方式间接访问 import 函数，然后用它来导入 os 模块，最终执行系统命令。

  • importlib 是 Python 3 中引入的一个模块，它提供了一个 API，用于动态地导入模块。这意味着你可以在运行时根据需要加载模块，而不是在程序启动时就加载所有模块。（具体可以看文档了解一下）

proot沙箱(拦截文件)

proot 的核心机制是拦截系统调用。当沙盒内的程序试图访问文件时，proot 会捕捉这个请求（通过 ptrace 机制），并进行“路径重写”

例如，沙盒内程序试图读取 /etc/passwd，proot 会拦截这个请求，并默默地将其重定向到你指定的目录，如 /home/user/sandbox/etc/passwd。这样，程序“以为”自己在访问整个系统，但实际上被限制在了特定文件夹中。

/usr/.../sitecustomize.py漏洞利用

而proot沙箱的利用点，就是/usr/.../sitecustomize.py的利用：

它是 Python 的“全局启动钩子”，任何 Python 进程启动时，都会在运行你的代码之前自动执行这个文件。

但这里要看清楚，是”运行你的代码之前”，也就是在沙箱环境开放之前，它就被自动执行了，所以如果往该文件里写shell，得到的必然是主机的shell

所以问题就显而易见了，你如果把/usr给映射到沙箱了，沙箱可以随便动主机的/usr，直接用沙箱的代码覆盖掉

原本的/usr/.../sitecustomize.py，这里完整的路径你也可以用递归ls来找到

这东西写进去以后，下次再运行沙箱（属于python进程启动）之前，就会先执行/usr/local/lib/python3.10/site-packages/sitecustomize.py里面的内容，即运行cat /flag，自然就能得到flag
