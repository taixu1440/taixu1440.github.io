[问题2/dataURI/文件包含/当前目录路径]JSON Beautifier

本题题面是一个json美化和预览的工具

这种美化预览的题，一般来说是要利用这种美化工具解析出我们可以利用的恶意代码。

通过信息收集我们发现路由/robots.txt，找到了两个接口

其中beautify.php应该就是返回接口的工具，能够返回一个路径，里面就是美化的结果

preview.php推测是预览的工具，存在一个文件包含的入口并提示hint:路径遍历

我们会发现正常GET:file=/flag file=/etc/passwd都提示文件不存在，说明绝对路径要么被拼接，要么被禁用

而使用路径遍历，我们会发现file=../../etc/passwd的确到了那里，只是读取的权限不够，并且**/flag是不存在的**

我们再尝试读preview.php本身的源码，仍提示未找到，故推知存在路径的拼接

当前目录的绝对路径

既然遍历到的了/etc/passwd，我们必须知道，也可通过遍历找到当前目录的绝对路径

果然，我们得到了源码

源码包含了一个config.php，这里面存有一些定义好的变量，由于是在当前目录，我们能够阅读一些定义好的变量

包括flag的路径是/secret/flag

稍微分析源码，即可发现源码对输入的路径进行了多重检测

入口点是第十行的file参数，在第13行用TMP_DIR进行拼接，也就是/tmp/json_preview

接着使用realpath()将路径转化为完全绝对的路径，随后检测总路径是否以TMP_DIR，即

/tmp/json_preview或SRC_API_DIR，即/var/www/html/src/api开头

很明显realpath()起不到过滤路径遍历的作用，**它只对../进行了一个绝对化，**这也能解释我们为啥能用

../../../proc/self/cwd/preview.php来读源码，因为它经过realpath()处理后变成了/var/www/html/src/api/preview.php，恰好以

/var/www/html/src/api开头；直接输preview.php则会被拼接为/tmp/json_preview/preview.php，当然找不到文件

因此我们只能通过这个接口读到当前目录/api下的内容与/tmp/json_preview/下的内容

接着读后半部分源码

这里的逻辑是检测file包含的文件是不是位于/tmp/json_preview/下且以tmp结尾，这也连接到了题面的生成器，

如果满足，则进入新一轮检测，这里直接把**$line内容给再包含一次**(25行)

读新一轮检测的思路，它先检测$line中有没有https等特定字符串，接着要求内容中有resource=这个字符串，并把位置返回给$pos，这里需要注意的是stripos只检测位置而不删除字符串

接着检测$resource = rawurldecode(substr($line, $pos + 9));，也就是从resource=的后9个字符串开始的子串恰好为FLAG_PATH，即/secret/flag，也就是line值以resource=/secret/flag结尾

所以我们只需要控制$line=php://filter/convert.base64-encode/resource=/secret/flag

[问题3/jwt/.git泄露]夜班审计台

利用链:

  1. 当前目录泄露的是 Git 对象，恢复后能看到两版线索：

    • 当前版允许 HS256，开发密钥是 ISCC_2026_JWT_DEBUG_KEY_#9527

    • 上一版保留了内部探针签名规则，服务端密钥是 ISCC_SERVER_SECRET_REAL

开发秘钥 ISCC_2026_JWT_DEBUG_KEY_#9527

作用是伪造登录票据 JWT。脚本里在 solve_audit_flag.py:36 到 solve_audit_flag.py:56 使用它，把 sub=auditor、role=auditor

的 payload 做 HS256 签名，生成 audit_token。没有这个秘钥，你进不了 [ /auditor/nodes ] 这个审计员页面。

服务端秘钥 ISCC_SERVER_SECRET_REAL

作用是给“内部节点查询”计算 HMAC。脚本里使用它，按旧规则对

f”{node_id}:{ts}“ 做 HMAC-SHA256。没有这个秘钥，即使你已经是审计员，提交节点查询时也过不了内部探针校验。

  1. 用 HS256 伪造 JWT，设 sub=auditor、role=auditor，拿到 /auditor/nodes 权限。

  2. 按旧规则计算：

    • node_id=core-storage-01

    • ts=当前 Unix 时间戳

    • sign = HMAC_SHA256(“ISCC_SERVER_SECRET_REAL”, f”{node_id}:{ts}“) 的十六进制

  3. 提交到 /auditor/nodes，返回flag
